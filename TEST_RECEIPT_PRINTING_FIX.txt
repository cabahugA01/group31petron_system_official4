WHAT WAS THE PROBLEM?
---------------------
Before: Receipt was RECALCULATING the total from items,
causing rounding differences and mismatches.

Example:
- System: ₱9,587.20
- Receipt: ₱9,587.18 ❌ (wrong due to recalculation)

After Fix: Receipt uses STORED total_amount directly.

Example:
- System: ₱9,587.20
- Receipt: ₱9,587.20 ✅ (correct - uses stored value)

====================================
TECHNICAL DETAILS (for developers)
====================================

File Changed: public/receipt.php
Line: ~454-469

Before (WRONG):
```php
$total = round($subtotal_display + $vat_display, 2); // Recalculates!
```

After (CORRECT):
```php
$total = (float)($sale['total_amount'] ?? $sale['total'] ?? 0); // Uses stored value!
```

This ensures the printed receipt always shows the
exact same total that was encoded in the database.
