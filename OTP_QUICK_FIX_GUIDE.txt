🔴 PROBLEM: "OTP verification failing even with correct code"

✅ ROOT CAUSE FOUND:
   Users are accessing the WRONG verification page!
   
   ❌ WRONG: verify_login_otp.php (for login 2FA)
   ✅ RIGHT: verify_otp.php (for password reset)

═══════════════════════════════════════════════════════════════════════
  CORRECT PASSWORD RESET FLOW
═══════════════════════════════════════════════════════════════════════

Step 1: forgot_password.php
   → User enters email/username
   → System generates OTP with token_type = 'reset'
   → Email sent with OTP code
   
Step 2: verify_otp.php?email=user@example.com
   → User enters 6-digit OTP from email
   → System verifies token_type = 'reset'
   → Checks expiration (5 minutes)
   
Step 3: forgot_password_reset.php?token=123456&email=...
   → User enters new password (twice)
   → Password updated in database
   → Token marked as used
   
Step 4: login.php
   → User logs in with new password
   → Success!

═══════════════════════════════════════════════════════════════════════
  DATABASE QUICK CHECK
═══════════════════════════════════════════════════════════════════════

Check if OTP exists:
-----------------------------------------
SELECT * FROM password_reset_tokens 
WHERE token = 'YOUR_OTP_CODE' 
  AND token_type = 'reset'
  AND is_used = 0
  AND expires_at > NOW();

If this returns NO ROWS:
  → OTP doesn't exist, expired, or already used
  → Request a new OTP

If this returns a ROW:
  → OTP is valid
  → Check if email matches the user_id

Get user email from token:
-----------------------------------------
SELECT u.email, u.status, prt.token, prt.expires_at, prt.is_used
FROM password_reset_tokens prt
JOIN users u ON prt.user_id = u.user_id
WHERE prt.token = 'YOUR_OTP_CODE'
  AND prt.token_type = 'reset';
