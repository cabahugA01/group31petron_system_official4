# Requirements Document

## Introduction

The Petron Station Management System currently displays pending stock-in deliveries on the Stock-In page (`manager_stock_in.php`). Users must navigate to this page to see if there are pending items requiring action. This feature adds notification badges to the system navigation menu to alert managers and administrators when there are pending stock-in items awaiting approval, improving visibility and reducing the need for manual checking.

## Glossary

- **Stock-In System**: The module responsible for approving pending staff-recorded deliveries and updating inventory
- **Badge**: A visual indicator (typically a number in a colored circle) displayed on navigation menu items to show counts of pending items
- **Pending Stock-In**: Deliveries in statuses 'Pending Stock-In', 'Ready for Stock-In', 'Validated', 'Verified', 'Partial Delivery', 'Damaged Items', or 'Adjusted'
- **Navigation Menu**: The sidebar navigation menu generated by `partials/rbac_menu.php`
- **Deliveries Oversight Table**: Database table `deliveries_oversight` containing delivery records with station assignment and status
- **Manager Role**: User role with permission to approve stock-in deliveries
- **Admin Role**: User role with oversight permissions across stations
- **Station ID**: Unique identifier for a Petron station location

## Requirements

### Requirement 1: Display Stock-In Badge Count

**User Story:** As a manager, I want to see a badge count on the Stock-In menu item, so that I know how many pending deliveries require my action without navigating to the page.

#### Acceptance Criteria

1. WHEN there are pending stock-in deliveries for the manager's station, THE Badge_Display_System SHALL display the count on the "Stock-In" navigation menu item
2. WHEN there are no pending stock-in deliveries, THE Badge_Display_System SHALL hide the badge from the "Stock-In" navigation menu item
3. THE Badge_Display_System SHALL count deliveries in statuses 'Pending Stock-In', 'Ready for Stock-In', 'Validated', 'Verified', 'Partial Delivery', 'Damaged Items', and 'Adjusted'
4. THE Badge_Display_System SHALL filter pending deliveries by the manager's station_id
5. THE Badge_Display_System SHALL display the badge using the existing badge styling pattern (red background #E30613, white text, 11px font, rounded)

### Requirement 2: Count Both Merchandise and Fuel Deliveries

**User Story:** As a manager, I want the badge to include both merchandise and fuel pending deliveries, so that I have a complete view of all pending stock-in work.

#### Acceptance Criteria

1. WHEN counting pending stock-in items, THE Badge_Counter SHALL include deliveries where delivery_type is 'merchandise'
2. WHEN counting pending stock-in items, THE Badge_Counter SHALL include deliveries where delivery_type is 'fuel'
3. THE Badge_Counter SHALL return the sum of pending merchandise and fuel deliveries as a single count

### Requirement 3: Update Badge in Real-Time

**User Story:** As a manager, I want the badge count to update automatically, so that I always see current information without refreshing the page.

#### Acceptance Criteria

1. WHEN the notification polling system fetches updates, THE Badge_Update_System SHALL retrieve the current stock-in count
2. WHEN the stock-in count changes, THE Badge_Update_System SHALL update the displayed badge value within 5 seconds
3. THE Badge_Update_System SHALL use the existing `notifications_api.php` polling mechanism
4. THE Badge_Update_System SHALL update the badge using the `data-sidebar-badge="mgr_stock_in"` attribute selector

### Requirement 4: Display Badge for Admin Role

**User Story:** As an admin, I want to see a stock-in badge count for my assigned station, so that I can monitor pending deliveries requiring manager approval.

#### Acceptance Criteria

1. WHEN an admin user views the navigation menu, THE Badge_Display_System SHALL display the stock-in badge if the admin has an assigned station_id
2. WHEN an admin user has no assigned station, THE Badge_Display_System SHALL not display a stock-in badge
3. THE Badge_Display_System SHALL filter pending deliveries by the admin's station_id
4. THE Badge_Display_System SHALL use the same counting logic as the manager role

### Requirement 5: Integrate with Existing Badge Infrastructure

**User Story:** As a system administrator, I want the stock-in badge to use the existing badge infrastructure, so that the implementation is consistent and maintainable.

#### Acceptance Criteria

1. THE Badge_Implementation SHALL add the badge count to the `$badges` array in `partials/header.php`
2. THE Badge_Implementation SHALL use the key 'mgr_stock_in' in the `$badges` array to match the menu item id
3. THE Badge_Implementation SHALL use the existing `data-sidebar-badge` attribute system for real-time updates
4. THE Badge_Implementation SHALL query the `deliveries_oversight` table using the same status filter as `manager_stock_in.php`
5. WHEN the page loads, THE Badge_Display_System SHALL execute the badge count query within 200ms

### Requirement 6: Handle Database Errors Gracefully

**User Story:** As a system user, I want the system to continue functioning even if the badge count fails, so that database errors don't break the navigation menu.

#### Acceptance Criteria

1. IF the badge count query fails, THEN THE Badge_Display_System SHALL set the badge count to zero
2. IF the badge count query fails, THEN THE Badge_Display_System SHALL not display an error message to the user
3. IF the `deliveries_oversight` table does not exist, THEN THE Badge_Display_System SHALL set the badge count to zero without throwing an exception

### Requirement 7: Update Badge When Deliveries Are Processed

**User Story:** As a manager, I want the badge count to decrease when I approve or process a delivery, so that the count accurately reflects remaining work.

#### Acceptance Criteria

1. WHEN a delivery status changes from a pending status to 'Completed' or 'Stock-In Done', THE Badge_Update_System SHALL decrease the badge count by one
2. WHEN a delivery status changes from 'Completed' back to a pending status, THE Badge_Update_System SHALL increase the badge count by one
3. WHEN multiple deliveries are batch-processed, THE Badge_Update_System SHALL update the badge count to reflect all changes within 5 seconds

### Requirement 8: Maintain Badge Visibility Rules

**User Story:** As a system user, I want the badge to follow standard visibility rules, so that the interface is consistent with other badges.

#### Acceptance Criteria

1. WHEN the sidebar is collapsed, THE Badge_Display_System SHALL hide the badge
2. WHEN the sidebar is expanded, THE Badge_Display_System SHALL show the badge if the count is greater than zero
3. WHEN the user hovers over the Stock-In menu item, THE Badge_Display_System SHALL keep the badge visible
4. THE Badge_Display_System SHALL position the badge using the same CSS flexbox layout as other navigation badges
